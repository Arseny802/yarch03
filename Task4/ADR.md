#### Ключевые факторы выбора текущего решения

1. **Соответствие ограничениям партнёра**:
   - SFTP как единственный доступный протокол
   - Отсутствие необходимости изменять инфраструктуру внешней системы

2. **Баланс между автоматизацией и сложностью**:
   - File Exporter как легковесное решение против ETL/ESB
   - Минимизация зависимостей от сторонних сервисов

3. **Комплаенс и безопасность**:
   - PGP-шифрование вместо VPN (меньше требований к инфраструктуре)
   - Локализация данных в соответствии с 152-ФЗ

4. **Поддержка пожилых пользователей**:
   - Человекочитаемое форматирование на уровне API
   - Резервный механизм 15-минутной выгрузки

5. **Экономическая эффективность**:
   - Использование существующих компонентов (Kafka, Redis)
   - Отсутствие лицензионных затрат на SFTP-решение

### **Недостатки, ограничения, риски**

#### 1. Архитектурные риски
* **Двойная система доставки** данных (API + файлы) создает риск рассинхронизации
* **Зависимость от Kafka** как единственного триггера обновлений
* **Жёсткая схема CSV** ограничивает гибкость при изменении данных

#### 2. Операционные риски
* **Безопасность данных**:
  * Утечка PGP-ключей
  * Риски при передаче файлов
  * Хранение секретов
* **Производительность**:
  * Ограничения Redis (до 100k операций/сек)
  * Узкое место в File Exporter (50 файлов/мин)

#### 3. Технические ограничения
* **Масштабируемость**:
  * Потоки обработки файлов
  * Емкость SFTP-хранилища
* **Надежность**:
  * Единая точка отказа в Redis
  * Зависимость от сетевой доступности

#### 4. Пользовательские риски
* **Сложность использования**:
  * Неинтуитивный формат CSV для партнеров
  * Технический язык в API-ответах
* **Поддержка**:
  * Обучение операторов
  * Техническая документация

#### 5. Долгосрочные риски
* **Технологический долг**:
  * Устаревшие версии ПО
  * Устаревание протоколов
* **Бизнес-риски**:
  * Изменение требований партнеров
  * Регуляторные изменения

#### 6. Мониторинг и observability
* **Слепые зоны**:
  * Отсутствие контроля после импорта
  * Нет метрик качества консультаций
* **Необходимые улучшения**:
  * Внедрение синтетического мониторинга
  * Расширение системы метрик

#### 7. План минимизации рисков
* **Технические меры**:
  * Внедрение HSM для ключей
  * Автоматизация мониторинга
  * Резервирование компонентов
* **Организационные меры**:
  * Регулярное обучение персонала
  * Аудит безопасности
  * Планирование обновлений
